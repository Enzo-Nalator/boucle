# Boucle ! — Jalons M1 à M3 (simulation, rendu, mode A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer le POC par un mode « Réseau infini » jouable au stylet : simulation de filières de recyclage en TypeScript pur, rendu Phaser façon Mini Metro, interface Svelte.

**Architecture:** `src/sim/` (aucune dépendance Phaser/DOM) porte tout l'état et les règles, avance par pas fixe de 50 ms et reçoit des `Command` sérialisables. `src/modes/endless.ts` est le directeur d'événements du mode A. `src/render/` dessine l'état et convertit le stylet en commandes ; `src/ui/` + `App.svelte` portent HUD, barre d'outils et écrans.

**Tech Stack:** TypeScript strict, Phaser 4.2.1, Svelte 5, Vite 6, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-02-boucle-gameplay-design.md` (M4 campagne et M5 équilibrage : plans séparés, après un test du mode A).

## Global Constraints

- Pas de Phaser, DOM ni `Math.random` dans `src/sim/` et `src/modes/` : tout l'aléa passe par le générateur à graine du monde (même graine + mêmes commandes ⇒ même état).
- Pas de temps fixe `DT = 0.05` s ; en rendu, jamais plus de 0.25 s de rattrapage par image.
- Carte de 1280×720 ; routes à segments 0°/45°/90° ; pas de texte dans la zone de jeu (HUD Svelte autorisé).
- Valeurs de départ des acteurs : celles du §3.2 de la spec, reprises dans la table de la Task 1.
- Le dossier n'est pas un dépôt git (l'utilisateur a refusé `git init`) : aucune étape de commit.
- Chaque tâche se termine par `npm test` et `npm run check` sans erreur.

## Review Focus

1. Route d'un acteur vers lui-même ou en doublon (même départ et arrivée) : refusée, aucun coût prélevé.
2. Placement d'un acteur à moins de 60 px d'un autre : refusé.
3. Budget insuffisant pour une commande : refusée sans effet partiel.
4. Acteur sans route sortante (ou route sortante vers un acteur qui refuse tout) : la file se remplit, pas de plantage, le débordement se déclenche.
5. Route supprimée avec des paquets en transit : paquets perdus comptés comme fuites, pas de plantage ; onglet masqué puis réaffiché : pas de saut de simulation.

### Task 3: Pas de temps — émission, routes, file, débordement

**Files:** Create `src/sim/step.ts`, `src/sim/actors.ts` (squelette `accepts`) · Test: `tests/sim/step.test.ts`

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces: `step(w: World, commands: Command[]): void` : (1) applique les commandes ; (2) chaque quartier émet à `w.emitRate` paquets/s (accumulateur `credit`) : matière tirée dans `w.activeRes`, `dirty` avec probabilité `w.contamination`, `reusable` avec probabilité 0.3, `kind:'dechet'`, log `emit` ; (3) retours différés des quartiers (`returns`) dont `at <= w.time` redeviennent des déchets ; (4) chaque acteur traite ses paquets à son débit (voir Tasks 4–5) ; (5) les paquets avancent sur les routes à `ROUTE_SPEED` px/s, capacité de route 4 paquets en transit (collecteur : 2 + 1 par niveau) ; (6) entretien et fin de partie (Task 6) ; (7) `w.time += DT`.
- Produces (`actors.ts`): `accepts(a: Actor, p: Packet): boolean` : recycleur ⇢ `kind==='dechet' && p.res===a.res`, fabricant ⇢ `kind==='matiere'`, quartier ⇢ `kind==='objet'`, tri ⇢ `kind==='dechet'`, réparateur ⇢ `kind==='dechet' && p.reusable`, décharge et collecteur ⇢ tout.
- Règles d'acheminement : un paquet qui sort d'un acteur choisit parmi ses routes sortantes dont la destination `accepts` le paquet, priorité décroissante puis round-robin (`a.rr`) ; sans route valide, il reste en file (blocage). Un paquet qui arrive dans un acteur dont la file est pleine attend en bout de route. Un paquet qui arrive dans un acteur qui ne l'accepte pas est perdu (log `leak`).
- Débordement : un quartier dont la file atteint sa capacité cumule `overflowT` ; au-delà de 5 s ⇒ `w.over = 'debordement'` ; `overflowT` repart à 0 dès qu'il repasse sous la capacité. Une fois `w.over` défini, `step` ne fait plus rien.

- [ ] **Step 1: Write the failing tests** (helper `tests/helpers.ts` : `run(w, seconds, cmds?)` appelle `step` `seconds/DT` fois) :
  - un quartier seul émet ≈ 0.5 paquet/s (entre 4 et 6 en 10 s) ;
  - deux mondes de même graine après 60 s ⇒ `JSON.stringify` identiques ;
  - quartier sans route : après 40 s, `w.over === 'debordement'` (Review Focus 4) ;
  - quartier → décharge reliés (route de 100 px) : après 30 s, `w.over === null` et ≥ 10 paquets absorbés (`leak` dans le log) ;
  - paquet envoyé vers un acteur qui ne l'accepte pas ⇒ `leak`, pas d'exception.
- [ ] **Step 2: Run** → FAIL.
- [ ] **Step 3: Implement** `step` en suivant l'ordre ci-dessus ; le traitement par acteur est un point d'extension `process(w, a)` dans `actors.ts` (Task 4 et 5).
- [ ] **Step 4: Run** `npm test && npm run check` → PASS.
